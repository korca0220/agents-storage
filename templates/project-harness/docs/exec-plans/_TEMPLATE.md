## 1. 목표 (Goal)

이 작업이 달성하려는 것을 **한 문단**으로 서술합니다. "왜 지금 하는가"를 포함하세요.

## 2. 범위 (Scope)

- **포함**:
  - (구체적인 변경 대상: 기능, 패키지, 파일군)
- **제외**:
  - (혼동될 수 있지만 이번엔 건드리지 않는 항목)

---

## 3. Done 기준 (Sprint Contract)

Generator와 Evaluator가 **사전에 합의**한 측정 가능한 완료 조건입니다. 애매한 표현("잘 작동한다") 금지. 전수 확인이 가능한 형태로 기술하세요.

- [ ] (기능) 사용자가 X 화면에서 Y를 누르면 Z가 저장된다 — 수동 시나리오 재현 가능
- [ ] (품질) 관련 단위 테스트 통과, [`agent-workflow.md`](../agent-workflow.md)의 "자동 검증" 명령 전부 통과
- [ ] (통합) 관련 앱/패키지에서 회귀 없음 (수동 검증 시나리오로 확인)
- [ ] (보안) 민감 정보(토큰, 개인정보)가 로그, 에러 리포트에 남지 않음

---

## 4. 실행 단계 (선택)

여러 단계로 나뉘고 단계마다 확인할 것이 다른 작업에만 씁니다. 루트 [`AGENTS.md`](../../AGENTS.md)의 4번 원칙 "Goal-Driven Execution"이 요구하는 "단계 → 검증" 쌍을 담는 자리입니다. 단일 변경이면 이 절을 지우세요.

- [ ] 1. (단계) → 검증: (통과 여부를 눈으로 확인할 수 있는 명령, 조건)
- [ ] 2. (단계) → 검증: …

커밋을 나눌 계획이 있으면 단계와 커밋을 1:1로 맞춰두면 리뷰가 쉬워집니다.

---

## 5. 테스트 시나리오

- **단위**: 테스트 대상 목록
- **위젯**: 핵심 화면의 렌더링, 상호작용 케이스
- **통합/E2E**: 필요 여부와 시나리오
- **수동**: 에이전트가 자동 검증할 수 없는 항목과 확인 방법
