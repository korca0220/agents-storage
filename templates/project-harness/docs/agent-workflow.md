# 에이전트 작업 흐름

루트 [`AGENTS.md`](../AGENTS.md)의 "작업 흐름" 표가 정하는 판단(작업 크기 → exec-plan, Evaluator 필요 여부)의 **상세 절차**입니다. 중형 이상 작업에서 [`exec-plans/_TEMPLATE.md`](./exec-plans/_TEMPLATE.md)로 계약을 쓸 때 함께 엽니다.

---

## Generator–Evaluator 6단계

| 단계 | 역할 | 하는 일 | 산출 |
| --- | --- | --- | --- |
| 1. 계약 | Generator + Evaluator | exec-plan으로 Done 기준을 **측정 가능한 체크리스트**로 합의 | `docs/exec-plans/YYYYMMDD-*.md` |
| 2. 구현 | Generator | Invariant, 스킬 규칙을 따라 구현하고 테스트 작성 | 코드 + 테스트 + 결정 로그 |
| 3. 로컬 검증 | Generator | 아래 "자동 검증" 명령 통과 | 통과 로그 |
| 4. 자기 리뷰 | Generator | diff를 스스로 다시 검토 | 리뷰 코멘트 |
| 5. 독립 평가 | Evaluator | **다른 세션, 다른 에이전트**로 체크리스트를 하나씩 재확인. 리뷰 서브에이전트(`.claude/agents/reviewer.md`)를 쓸 수 있다 | Pass/Fail + 보완 지시 |
| 6. Handoff | Generator | exec-plan의 Handoff 메모에 현재 상태, 다음 단계, 주의점 기록 | exec-plan 업데이트 |

5단계를 사람이 맡아도 됩니다. 실제로 운영해 보면 평가자 자리는 결국 사람이 채우는 경우가 많습니다.

---

## 하네스 변경 후 점검

하네스 파일을 바꾼 에이전트는 변경 크기에 맞춰 점검합니다. 모든 문서 변경에 전체 감사를 돌리지 않습니다.

| 변경 범위 | 점검 | 완료 기준 |
| --- | --- | --- |
| 소형: 단일 문서의 문구, 링크 수정 | 변경 문서와 직접 참조 문서의 링크, 용어 정합성 | 확인 결과를 작업 보고에 기록 |
| 중형: ADR, 정책, 스킬 추가/수정 | 영향 받는 `AGENTS.md`, ADR, 스킬, 템플릿을 읽고 충돌과 누락 확인 | 영향 범위와 결과를 기록 |
| 대형: 훅, 자동화, 여러 정책 원천 변경 | 하네스 전체 감사 | 감사 결과와 로그를 남김 |

## Context Reset

긴 작업에서 컨텍스트가 한계에 가까워지면 서둘러 마무리하는 경향이 생깁니다. 자동 요약보다 **Context Reset + Handoff 메모**가 더 안정적입니다. 한계가 가까우면 exec-plan을 업데이트하고 새 세션으로 넘깁니다.

## Observability

에이전트가 **스스로** 실행 결과를 확인할 수 있어야 이 흐름이 돌아갑니다.

**자동 검증 (3단계)**

| 목적 | 명령 |
| --- | --- |
| Lint | `{{명령}}` |
| 포맷 | `{{명령}}` |
| 테스트 | `{{명령}}` |
| 코드 생성 재현 | `{{명령}}` |

**수동 검증 (5단계)**

| 대상 | 방법 |
| --- | --- |
| 앱 실행 | `{{명령}}` |
| 실기기 | {{내부 테스트 배포 경로}} |

**격리 원칙**

- 하나의 exec-plan은 하나의 브랜치에서만 진행합니다. 여러 에이전트가 같은 브랜치를 공유하지 않습니다.
- 민감 정보(API 키, 토큰)는 커밋하지 않습니다. {{주입 방식}}

**작업 종료 보고 순서**

1. 자동 검증 결과 (성공/실패)
2. 수정한 패키지 목록
3. 실행한 수동 시나리오와 결과
4. 해결하지 못한 로그, 에러, 경고
